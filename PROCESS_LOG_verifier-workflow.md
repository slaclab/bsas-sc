## Intent

Add a test-side verifier flow that captures a merged PV snapshot while the writer runs, stops the writer, then validates the generated HDF5 file contents against the captured event data | Constraints: keep changes in `test/`, reuse existing EPICS/PVXS/HighFive patterns, stay C++11, fail non-zero on any mismatch | Done when: the full-stack test starts capture, stops writer, runs verification, and the verifier reports success only for correct files

## Requirements

### Functional Requirements
- FR-1: Provide a `verifier` host executable under `test/` that can run in capture mode and verify mode.
- FR-2: Capture the merged PV snapshot to a temp file while the writer is running.
- FR-3: Validate every HDF5 file generated by the writer against the captured snapshot and the expected HDF5 layout.
- FR-4: Report missing files, missing datasets, schema mismatches, and data mismatches with non-zero exit status.

### Acceptance Criteria
- AC-1: The full-stack script can start verifier capture, stop the writer, stop capture, and then run verification successfully.
- AC-2: The verifier rejects a file with missing columns or incorrect row data.
- AC-3: The verifier reads the file read-only and does not alter any generated artifacts.

### Non-Functional Constraints
- NFC-1: Keep the implementation minimal and aligned with existing `test/*App` build patterns.
- NFC-2: Use the same PV naming and separator defaults already used by the merger/writer harness.

### Out of Scope
- No changes to merger or writer algorithms.
- No new persistent runtime service or daemon.
